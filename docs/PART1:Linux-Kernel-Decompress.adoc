[.lead]
This document is a complete technical reference for the ARM32 Linux compressed kernel
boot sequence.  It covers every step from the build system producing the `zImage`
artifact, through the self-decompressing bootstrap loader in `head.S`, to the final
handoff to `stext` in the uncompressed `vmlinux`.

All addresses and register values shown are real values captured from a live GDB
session on a QEMU ARM (Cortexa15) machine built with a Yocto Poky toolchain
(linux-playground 6.12.56).

[NOTE]
====
*Reference*: https://people.kernel.org/linusw/how-the-arm32-linux-kernel-decompresses[How the ARM32 Linux kernel decompresses] — Linus Walleij's article provided the
architectural context for this document.

*Source repository*: https://github.com/Abhishekojha38/yocto-playground.git[yocto-playground]
====

== Overview

=== Why Compressed Kernels?

ARM traditionally ships compressed kernels for two important reasons:

* *Storage savings*: `vmlinux` is ~11-12 MB; `zImage` is ~4-5 MB.  That is a saving
  of over 50%.  Flash memory is expensive on embedded SoCs and every byte matters.
* *Faster load time*: the time the CPU spends decompressing is shorter than the time
  required to transfer the extra 6-7 MB from slow NAND flash or eMMC.

The trade-off is added complexity: the kernel image must bootstrap a mini-decompressor
before any real kernel code runs.

=== Complete Boot Flow at a Glance

.Complete ARM32 compressed kernel boot flow — all 8 phases

image::../../images/diag-boot-overview.png[Boot overview, 740, align=center]

[cols="1,3,4", options="header", width="100%"]
|===
| Phase | Code Location | Key Action

| 1 | Bootloader (U-Boot / EFI)
| Load `zImage`, set `r0/r1/r2`, jump to entry

| 2 | `head.S start:`
| NOP sled, save ATAGS, enter SVC mode

| 3 | `head.S` — `AUTO_ZRELADDR`
| Locate RAM base, compute `ZRELADDR (r4)`

| 4 | `head.S restart:`
| Set up stack (`sp`), malloc (`r10`), get image size (`r9`)

| 5 | `head.S` — overwrite checks
| Check A + B both fail → must relocate

| 6 | `head.S` — relocation
| Copy decompressor backwards above kernel destination

| 7 | `head.S wont_overwrite:` + `misc.c`
| GOT fixup, BSS clear, `decompress_kernel()`

| 8 | `head.S __enter_kernel`
| Cache off, restore `r0/r1/r2`, `mov pc, r4` → `stext`
|===

== zImage Build Pipeline

Before examining runtime behaviour it is essential to understand what the build system
assembles.  Running `make ARCH=arm zImage` triggers the following chain of
transformations.

.Build pipeline: vmlinux → Image → piggy.gzip → zImage
image::../../images/diag-build-pipeline.png[Build pipeline, 640, align=center]

=== Build Artefacts

[cols="2,4,3", options="header", width="100%"]
|===
| File | Description | Path

| `vmlinux`
| Original ELF kernel — all symbols, uncompressed (~11 MB).
| `./vmlinux`

| `System.map`
| Symbol→address lookup table used for debugging.
| `./System.map`

| `Image`
| Raw binary extracted from `vmlinux` by `objcopy`.
  Strips the ELF header, `.comment` section, and debug symbols.
| `./arch/arm/boot/Image`

| `head.o`
| ARM assembly startup code — takes control from the bootloader.
  Source: `arch/arm/boot/compressed/head.S`.
| `compressed/head.o`

| `piggy.gzip`
| `gzip -9` compressed `Image` payload (~4.8 MB).
| `compressed/piggy.gzip`

| `piggy.gzip.o`
| Linkable wrapper around `piggy.gzip`.
  `piggy.gzip.S` uses `.incbin` to embed it between
  `input_data` and `input_data_end` labels.
| `compressed/piggy.gzip.o`

| `misc.o`
| C decompression glue — provides `decompress_kernel()`.
| `compressed/misc.c`

| `compressed/vmlinux`
| Linked ELF: `head.o + misc.o + piggy.gzip.o`.
  This is the *bootstrap loader*, NOT the real kernel.
| `compressed/vmlinux`

| `zImage`
| Final `objcopy -O binary` of `compressed/vmlinux`.
  This is what the bootloader loads into RAM.
| `./arch/arm/boot/zImage`
|===

=== Step-by-Step Build Commands

==== Step 1 — Generate `Image` (raw binary)

`objcopy` extracts loadable sections and writes a flat binary:

[source,bash]
----
arm-poky-linux-gnueabi-objcopy \
    -O binary       \  # output format: flat binary
    -R .comment     \  # remove .comment section
    -S              \  # strip all debug symbols
    vmlinux Image
----

==== Step 2 — Compress to `piggy.gzip`

The raw `Image` is piped through `gzip` with maximum compression.
If gzip fails the output file is deleted atomically to avoid leaving a corrupt artefact:

[source,bash]
----
(cat Image | gzip -n -f -9 > arch/arm/boot/compressed/piggy.gzip) \
    || (rm -f arch/arm/boot/compressed/piggy.gzip; false)
----

==== Step 3 — Wrap as `piggy.gzip.o`

`piggy.gzip.S` uses the `.incbin` assembler directive to embed `piggy.gzip` between
two labels that `head.S` uses as boundaries at runtime:

.piggy.gzip.S showing input_data / input_data_end boundaries
image::../../images/piggy-linker-script.png[Piggy linker script, 560, align=center]

[source,bash]
----
arm-poky-linux-gnueabi-gcc \
    -DZIMAGE -c             \
    -o compressed/piggy.gzip.o \
    arch/arm/boot/compressed/piggy.S
----

The name "piggy" (as in "piggyback") describes its role: carrying the compressed
kernel payload on the back of the bootstrap loader.

==== Step 4 — Link `compressed/vmlinux`

The linker combines `head.o`, `misc.o`, and `piggy.gzip.o` using `vmlinux.lds`.
The result is *not* the real kernel — it is the self-decompressing bootstrap ELF.

==== Step 5 — Extract `zImage`

[source,bash]
----
arm-poky-linux-gnueabi-objcopy \
    -O binary compressed/vmlinux arch/arm/boot/zImage
----

== Bootloader Handover

The bootloader (U-Boot, EFI, or the legacy Angel monitor) places `zImage` into
physical RAM and jumps to its entry point.
Russell King's
https://www.armlinux.org.uk/developer/booting.php[Booting ARM Linux] document (2002)
defines the ABI that all ARM bootloaders must follow.

=== Bootloader Register ABI

On entry to `zImage`, the CPU must be in Supervisor (SVC) mode with interrupts,
MMU, and caches disabled.

[cols="1,2,4", options="header", width="100%"]
|===
| Register | Value | Meaning

| `r0`
| `0x00000000`
| Must be zero (reserved for future use)

| `r1`
| Machine ID or `0`
| Legacy machine type number.  Ignored on Device Tree kernels.

| `r2`
| Physical address
| Pointer to ATAGs list **or** Device Tree Blob (DTB) in physical RAM.

| `pc`
| `zImage` load address
| CPU jumps here — execution starts at `head.S start:` label.
|===

=== Initial RAM Layout

.Physical RAM state immediately after bootloader hands over control
image::../../images/diag-ram-initial.png[Initial RAM layout, 680, align=center]

In this QEMU session the key addresses are:

[source]
----

zImage loaded   = 0x40010000   (PC starts here)
DTB in r2       = 0x48000000
ZRELADDR (r4)   = 0x40208000   (= RAM base + TEXT_OFFSET)
----

== head.S Execution — Phase by Phase

`arch/arm/boot/compressed/head.S` is the heart of the decompressor.  It is pure ARM
assembly with no C library, and must be *fully position-independent (PIC)* because it
runs before the GOT is patched and before it knows exactly where in RAM it was loaded.

.head.S high-level initialization flow
image::../../images/kernel-initialization-graph.png[Initialization graph, 560, align=center]

=== NOP Sled and Magic Words

Execution begins at the `start:` symbol.  Legacy `a.out`-format bootloaders jump
32 bytes (8 instructions) into the image to skip a fake `a.out` header.
The 8 NOPs fill exactly those 32 bytes, preserving compatibility:

[source,armasm]
----
start:
    __initial_nops          @ 3 NOPs (mandatory prefix)
    .rept 5
    __nop                   @ 5 more NOPs
    .endr
#ifndef CONFIG_THUMB2_KERNEL
    __nop                   @ 1 final NOP (ARM state only)
#endif
    W(b)    1f              @ jump over magic word table

    .word   _magic_sig      @ 0x016F2818 — zImage identifier
    .word   _magic_start    @ absolute load address
    .word   _magic_end      @ zImage end address
    .word   0x04030201      @ endianness flag
    .word   0x45454545      @ secondary magic number
    .word   _magic_table    @ additional data table pointer
----

.GDB showing the NOP sled and magic words at 0x40010000
image::../../images/move-pc-to-next-inst-1.png[NOP sled, 640, align=center]

.PC advancing through the NOPs to the first real instruction
image::../../images/move-pc-to-next-inst-2.png[PC advance, 640, align=center]

[TIP]

The `0x40010000` address corresponds to the `.text` section base.
You can verify this with:
`arm-poky-linux-gnueabi-objdump -D arch/arm/boot/compressed/vmlinux | head -30`

=== Saving ATAGS / DTB Pointer and Architecture ID

Immediately after jumping over the magic words the code saves the bootloader-provided
values before anything can corrupt them:

.head.S code that saves r1 and r2 on entry
image::../../images/head.s-atags.png[ATAGS code, 600, align=center]

[source,armasm]
----
1:
    mrs     r9, cpsr            @ save current processor mode for later
    mov     r7, r1              @ save architecture ID (or 0 for DT boots)
    mov     r8, r2              @ save ATAGs / DTB physical address
----

.GDB showing the save instructions executing
image::../../images/save-atags.png[Save ATAGs GDB, 600, align=center]

.Register dump: Arch ID = 0xFFFFFFFF, ATAGs/DTB = 0x48000000
image::../../images/arch-id-atags-pointer.png[Arch ID and ATAGS, 560, align=center]

`r7` and `r8` are preserved throughout the entire decompressor and restored as `r1`
and `r2` in `__enter_kernel` (see <<enter_kernel>>).

=== Entering SVC Mode and Disabling IRQ/FIQ

The `safe_svcmode_maskall` macro forces the CPU into Supervisor mode and masks all
interrupts.  This is required because the decompressor runs with no interrupt vectors
or handlers configured:

.safe_svcmode_maskall code sequence
image::../../images/enter-svc-mode.png[Enter SVC mode, 560, align=center]

[source,armasm]
----
    safe_svcmode_maskall r0  @ force SVC mode, mask IRQ and FIQ
    msr     spsr_cxsf, r9    @ save original boot mode in SPSR
----

.CPSR = 0x1D3 — SVC mode confirmed, IRQ and FIQ masked
image::../../images/svc-r0-cpsr.png[SVC CPSR, 500, align=center]

Decoding `CPSR = 0x1D3`:

[source]
----
0x1d3 = 0000 0000 0000 0000 0000 0001 1101 0011
                                         ^^^^^
bits [4:0] = 0x13  →  Supervisor (SVC) mode
bit  [6]   = 1     →  FIQ masked
bit  [7]   = 1     →  IRQ masked
bit  [5]   = 0     →  ARM state (not Thumb)
bits[31:28]= 0000  →  NZCV condition flags cleared
----

[cols="1,1,1,3", options="header", width="80%"]
|===
| Field | Bits | Value | Meaning

| Mode  | [4:0] | `0x13` | Supervisor (SVC) mode
| T     | [5]   | `0`    | ARM state (not Thumb)
| F     | [6]   | `1`    | FIQ masked
| I     | [7]   | `1`    | IRQ masked
| NZCV  | [31:28]| `0000`| Condition flags cleared
|===

=== Locating Physical Memory Base (AUTO_ZRELADDR)

The decompressor needs to know where physical RAM starts so it can compute the
final kernel load address.  On platforms with `CONFIG_AUTO_ZRELADDR` (the modern
default), it derives this from the program counter using a bitmask:

.AUTO_ZRELADDR code in head.S
image::../../images/find-physical-memory.png[Find physical memory, 600, align=center]

[source,armasm]
----
    mov     r0, pc              @ r0 = current PC (inside zImage)
    and     r0, r0, #0xf8000000 @ mask to 128 MiB-aligned block
    @ r0 = physical RAM base
----

.GDB: r0 = 0x40000000 after masking the PC
image::../../images/find-phy-addr.png[Find physical address, 500, align=center]

[NOTE]
====
*Why `0xF8000000`?*
This mask preserves the top 5 bits of the 32-bit address, which encode which
128 MiB block of RAM is active.  The lower 27 bits (offset within the block)
are discarded.

[source]
----
0xF8000000 = 1111 1000 0000 0000 0000 0000 0000 0000
              ─────                                   ← top 5 bits kept
Example:
  PC     = 0x400100A4
  mask   = 0xF8000000
  result = 0x40000000  ← physical RAM base
----
====

For platforms where physical RAM does *not* start at a 128 MiB boundary,
`fdt_check_mem_start()` validates and optionally corrects `r0` using the DTB's
memory nodes:

.DTB at 0x48000000 — first word 0xEDFE0DD0 = byte-swapped FDT magic 0xD00DFEED ✓
image::../../images/fdt-mem-check.png[FDT mem check, 600, align=center]

.Memory dump confirming valid FDT header
image::../../images/memory-address.png[Memory address, 600, align=center]

=== Computing the Final Kernel Load Address (ZRELADDR)

Once the RAM base is in `r0`, `TEXT_OFFSET` is added to produce `ZRELADDR` — the
address where the decompressed kernel will be written.  `TEXT_OFFSET` is defined in
`arch/arm/Makefile`:

.TEXT_OFFSET addition code in head.S
image::../../images/textofs.png[TEXT offset, 580, align=center]

[source,armasm]
----
    /* Determine final kernel image address */
    add     r4, r0, #TEXT_OFFSET    @ r4 = RAM_BASE + TEXT_OFFSET
    @ For this board: 0x40000000 + 0x208000 = 0x40208000
----

.GDB confirming r4 = 0x40208000 (ZRELADDR)
image::../../images/text-offset.png[Text offset GDB, 600, align=center]

[source]
----
(gdb) info registers r4 r0
r4  =  0x40208000   (1075871744)
r0  =  0x40000000   (1073741824)
----

[NOTE]
====
The `0x208000` `TEXT_OFFSET` used here is the Qualcomm-style value, where the first
2 MB of RAM (`0x200000`) is reserved for shared memory with the modem CPU.

Most conventional platforms use `TEXT_OFFSET = 0x8000` (32 KB).  The 32 KB
convention exists because:

* ARM systems traditionally place interrupt vectors at `0x00000000`
* ATAGs are typically placed at `0x00000100`
* The kernel needs 16 KB (`0x4000`) *below* `TEXT_OFFSET` for its initial page table
====

=== Setting Up the Page Table and Enabling Caches

Decompressing ~10 MB in software is slow.  Enabling the CPU's I-cache and D-cache
dramatically speeds it up.  ARM caches require a page table even for a flat 1:1
virtual=physical mapping:

* The 16 KiB page table is placed at `r4 - 0x4000` (just below ZRELADDR).
* It is only set up if it won't overwrite the decompressor itself.
* It covers both the decompressor region and kernel destination with cacheable,
  bufferable attributes.

[source,armasm]
----
    mov     r0, pc
    cmp     r0, r4              @ is PC < ZRELADDR?
    ldrcc   r0, .Lheadroom      @ load safety headroom
    addcc   r0, r0, pc
    cmpcc   r4, r0              @ will the page table fit safely?
    orrcc   r4, r4, #1          @ LSB=1 means cache_on was skipped
    blcs    cache_on            @ call cache_on if safe
----

`cache_on` selects the correct cache-enable routine from the `proc_types` table
by matching the CPU ID register (`CP15 c0`).  This handles all ARM variants from
ARMv4 through ARMv7.

==== Position-Independent Stack Calculation (LC1)

The decompressor must be fully position-independent — it cannot know where in RAM
it was loaded, so stack and heap addresses cannot be hard-coded.  Instead, they are
stored as *relative offsets* in the `LC1` data structure:

[source,armasm]
----
    adr     r1, LC1             @ r1 = runtime address of LC1 label
    ldr     sp, [r1]            @ sp = LC1[0]  (relative offset)
    ldr     r6, [r1, #4]        @ r6 = LC1[1]  (relative offset)
    add     sp, sp, r1          @ sp = runtime_LC1 + offset = absolute stack top
    add     r6, r6, r1          @ r6 = runtime_LC1 + offset = absolute _edata

...

LC1:
    .word   .L_user_stack_end - LC1   @ LC1[0] = 0x009FAA10
    .word   _edata - LC1              @ LC1[1] = 0x009F99F8
----

== Overwrite Safety Analysis

The most subtle part of the decompressor is the check that determines whether it is
safe to decompress in place, or whether the decompressor must first move itself to
a higher address before inflating the payload.

=== The Problem

The decompressor will inflate ~25.4 MiB starting at `ZRELADDR (0x40208000)`.
But the decompressor itself is executing from `0x40010000` to `0x40A1ECC0` — a range
of ~9.5 MiB.  Crucially, `0x40208000` falls *inside* that range:

.Overlap analysis — decompressor and kernel destination regions
image::../../images/diag-overlap-check.png[Overlap check diagram, 700, align=center]

=== Check A — Is the Kernel Destination Above the Decompressor?

This check asks: will the decompressed kernel be placed *completely above* the
decompressor's working area (code + stack + malloc + page directory)?

[source,armasm]
----
    add     r10, r10, #16384        @ r10 += 16 KiB (page directory size)
    cmp     r4, r10                 @ is r4 (ZRELADDR) >= r10?
    bhs     wont_overwrite          @ PASS → safe to decompress in place
    @ (falls through on FAIL → proceed to Check B)
----

[cols="2,2,5", options="header", width="100%"]
|===
| Variable | Value | Meaning

| `r4` | `0x40208001`
| ZRELADDR (LSB=1 is the Thumb interwork bit — effective address = `0x40208000`)

| `r10` | `0x40A1ACC0`
| Malloc top

| `r10 + 16K` | `0x40A1ECC0`
| End of decompressor working area (page-dir added)

| `r10 + 16K + 16K` | `0x40A22CC0`
| Threshold that `r4` must *exceed* to pass Check A

| *Result* | *FAIL*
| `0x40208001 < 0x40A22CC0` — kernel starts *inside* the decompressor area
|===

=== Check B — Does the Decompressed Kernel Fit Below the Decompressor?

This check asks: does the decompressed kernel end *before* it reaches the decompressor
code?  (i.e. does the entire kernel fit in the gap below where we are running?)

[source,armasm]
----
    add     r10, r4, r9             @ r10 = r4 + inflated_size = end-of-kernel
    adr     r9, wont_overwrite      @ r9  = runtime addr of wont_overwrite label
    cmp     r10, r9                 @ is end-of-kernel <= wont_overwrite?
    bls     wont_overwrite          @ PASS → safe to decompress in place
    @ (falls through on FAIL → must relocate)
----

== Self-Relocation

Since both overwrite checks failed, the decompressor must move itself to a safe
location above `0x41B79D2D` before inflating the payload.

=== Computing the Relocation Destination

The destination must be above the kernel end, with enough clearance that the
relocation trampoline (the copy loop itself) doesn't overwrite itself mid-copy:

[source,armasm]
----
    /* r10 = end-of-kernel = 0x41B79D2D */
    add     r10, r10, #((reloc_code_end - restart + 256) & ~255)
    bic     r10, r10, #255
    /* r10 = 256-byte aligned base above end-of-kernel */
    /* GDB confirms: r10 = 0x41B7A600 */

    adr     r5, restart
    bic     r5, r5, #31         @ align source start down to 32 bytes
    /* r5 = source start ≈ 0x40010000 */
----

[source]
----
(gdb) info registers r6 r10
r6   = 0x40A09CA8     <<< _edata  (source end)
r10  = 0x41B7A600     <<< relocation destination base
----

=== Why Copy Backwards?

[source,armasm]
----
1:  ldmdb   r6!, {r0 - r3, r10 - r12, lr}  @ load 8 words from source, decrement r6
    cmp     r6, r5                          @ reached source start?
    stmdb   r9!, {r0 - r3, r10 - r12, lr}  @ store 8 words to dest, decrement r9
    bhi     1b                              @ loop until done
----

.Three-stage memory view: before copy / during backward copy / after relocation
image::../../images/diag-relocation.png[Relocation diagram, 700, align=center]

[NOTE]
====
Since destination base (`0x41B7A600`) > source base (`0x40010000`), a *forward*
copy would risk the write pointer overtaking the read pointer if ranges overlapped.

The *backward* copy (`ldmdb` / `stmdb`) reads from the highest source address
first — each word is safely consumed before the destination pointer could alias it.
This guarantees correctness even when source and destination partially overlap.
====

=== Jumping to Relocated Code

After the copy the decompressor flushes the D-cache and branches to the relocated
`restart:` entry:

[source,armasm]
----
    mov     r0, r9              @ start of relocated zImage
    add     r1, sp, r6          @ end of relocated zImage
    bl      cache_clean_flush   @ flush D-cache over copied range

    badr    r0, restart         @ PC-relative address of restart:
    add     r0, r0, r6          @ apply relocation delta
    mov     pc, r0              @ JUMP to relocated restart: at 0x41B7A600+offset
----

🔹 **What is proc_info?**

`proc_info` (often called `proc_info_list` in the kernel) is a per-CPU descriptor structure used very early during boot.
👉 It tells the kernel:
How to identify a CPU
Which functions to use for that CPU (cache, MMU, etc.)

[source,c]
----
/*
 * Note!  struct processor is always defined if we're
 * using MULTI_CPU, otherwise this entry is unused,
 * but still exists.
 *
 * NOTE! The following structure is defined by assembly
 * language, NOT C code.  For more information, check:
 *  arch/arm/mm/proc-*.S and arch/arm/kernel/head-armv.S
 */
struct proc_info_list {
	unsigned int	 cpu_val;
	unsigned int	 cpu_mask;
	unsigned long	 __cpu_mmu_flags;	/* used by head-armv.S */
	unsigned long	 __cpu_flush;		/* used by head-armv.S */
	const char	 *arch_name;
	const char	 *elf_name;
	unsigned int	 elf_hwcap;
	struct proc_info_item *info;
#ifdef MULTI_CPU
	struct processor *proc;
#else
	void		 *unused;
#endif
};
----

[source,armasm]
----
/*
 * Clean and flush the cache to maintain consistency.
 *
 * On entry,
 *  r0 = start address
 *  r1 = end address (exclusive)
 * On exit,
 *  r1, r2, r3, r9, r10, r11, r12 corrupted
 * This routine must preserve:
 *  r4, r6, r7, r8
 */
		.align	5
cache_clean_flush:
		mov	r3, #16             @ Call the function located at offset 16 inside each proc_types entry
		mov	r11, r1             @ save end address
		b	call_cache_fn

call_cache_fn:
		Detects which CPU you are running on
		Walks through a table of supported CPUs (proc_types)
		Finds a matching entry
		Calls the correct cache operation function for that CPU
----

[NOTE]
====
The relocated `restart:` re-executes the stack/malloc setup (`sp`, `r6`, `r10`)
but now at the new high-memory addresses.  It then falls straight through the
overwrite checks (which now both pass) into `wont_overwrite:`.
====

'''

== wont_overwrite: — GOT Fixup, BSS Clear, and Decompression

All paths converge at `wont_overwrite:` — whether the decompressor relocated
itself or arrived here directly.  The C runtime must be prepared before calling
`decompress_kernel()`.

=== Checking the Relocation Delta

[source,armasm]
----
wont_overwrite:
    adr     r0, LC0
    ldmia   r0, {r1, r2, r3, r11, r12}
    sub     r0, r0, r1          @ delta = runtime_LC0 - linked_LC0
    @ if delta == 0: we are at the linked address (no relocation needed)
    orrs    r1, r0, r5          @ r5 = appended DTB size (0 if absent)
    beq     not_relocated       @ skip GOT fixup if both zero
----

=== GOT Fixup

The Global Offset Table (GOT) contains absolute pointers to global variables in
`misc.c`.  After relocation these are stale — they point to the old location.
Each entry is patched with the relocation delta:

[source,armasm]
----
    add     r11, r11, r0        @ GOT start += delta
    add     r12, r12, r0        @ GOT end   += delta
    add     r2,  r2,  r0        @ BSS start += delta
    add     r3,  r3,  r0        @ BSS end   += delta

1:  ldr     r1, [r11, #0]       @ load GOT entry (absolute pointer)
    add     r1, r1, r0          @ add relocation delta
    cmp     r1, r2              @ if entry >= BSS start ...
    cmphs   r3, r1              @ ... and BSS end > entry ...
    addhi   r1, r1, r5          @ ... also add appended DTB size (BSS bump)
    str     r1, [r11], #4       @ store patched entry, advance
    cmp     r11, r12
    blo     1b                  @ loop until all GOT entries patched
----

🔹 **What is the Global Offset Table (GOT)?**
The GOT is a table of pointers used by dynamically-linked executables to resolve the addresses of global variables and functions at runtime.
👉 In this context, it’s used to fix the addresses of global variables in `misc.c` after the decompressor has been relocated to a new memory location.

[source,c]
----
/*
 * Global Offset Table (GOT) for the decompressor.
 * This table is used to store the absolute addresses of global variables
 * in misc.c, which are used by the decompressor.
 */
got:
    .long   _edata              @ end of initialized data
    .long   _end                @ end of BSS
    .long   _etext              @ start of code
    .long   _end                @ end of BSS
---- 

----
new_address = old_address(r1) + delta(r0)
----

=== BSS Clear

All uninitialized global variables in `misc.c` live in `.bss`.
The C standard requires them to be zero on entry:

[source,armasm]
----
not_relocated:
    mov     r0, #0
1:  str     r0, [r2], #4        @ clear word, advance pointer
    str     r0, [r2], #4        @ (unrolled 4 stores per iteration)
    str     r0, [r2], #4
    str     r0, [r2], #4
    cmp     r2, r3              @ reached end of BSS?
    blo     1b
----

[source,armasm]
----
r0  = relocation delta
r11 = GOT start
r12 = GOT end
r2  = BSS start
r3  = BSS end
r5  = appended DTB size (extra bump)
----

=== Calling decompress_kernel()

With the C runtime ready, execution calls into `misc.c`:

[source,armasm]
----
    mov     r0, r4              @ r0 = ZRELADDR (output start = 0x40208000)
    mov     r1, sp              @ r1 = malloc base (stack top)
    add     r2, sp, #MALLOC_SIZE @ r2 = malloc end (+ 64 KiB)
    mov     r3, r7              @ r3 = architecture ID
    bl      decompress_kernel   @ call into misc.c
----

== Cache Flush, Cache Off, and __enter_kernel

=== Flush and Turn Off Caches

The decompressor flushes the D-cache over the newly-written kernel image (to make
it coherent for instruction fetch), then disables the MMU and caches as required
by the ARM booting ABI:

[source,armasm]
----
    get_inflated_image_size r1, r2, r3  @ r1 = end address of inflated kernel
    mov     r0, r4                      @ r0 = start = ZRELADDR
    bl      cache_clean_flush           @ flush D-cache over entire kernel image
    bl      cache_off                   @ disable MMU, I-cache, D-cache
----

`cache_off` selects the correct disable sequence from `proc_types` based on the
CPU ID, invalidates TLBs where applicable, and issues DSB/ISB barriers.

=== __enter_kernel — Final Register Restore and Jump

[source,armasm]
----
__enter_kernel:
    mov     r0, #0      @ r0 must be 0 (ARM boot ABI)
    mov     r1, r7      @ restore MachID (saved at entry in Phase 2)
    mov     r2, r8      @ restore DTB pointer (saved at entry in Phase 2)
    mov     pc, r4      @ jump to stext at ZRELADDR = 0x40208000
----

[NOTE]
====
At the moment `pc = 0x40208000`, execution is *identical* to a bootloader
that loaded the uncompressed `vmlinux` directly to `TEXT_OFFSET`.
The entire decompressor is now irrelevant.
====

=== Final Memory State at stext

| Register | Value | Meaning for vmlinux

| `r0` | `0x00000000` | Must be zero — ARM boot ABI requirement
| `r1` | `0xFFFFFFFF` | Machine ID (ignored by DT kernels, passed through for legacy)
| `r2` | `0x48000000` | DTB physical address — parsed by `of_scan_flat_dt()` in `start_kernel`

=== What Happens in vmlinux (stext)

The uncompressed kernel's `arch/arm/kernel/head.S` takes over:

. Enable the MMU and set up initial page tables at `ZRELADDR - 0x4000`.
. Call `__mmap_switched`: copy `.data` from ROM if needed, clear BSS, set up stack.
. Call `start_kernel()` in `init/main.c` — printk, scheduler, drivers, filesystems.

[NOTE]
====
The appended DTB (`ARM_APPENDED_DTB`) and ATAGs processing code lives *only* in
the compressed decompressor (`head.S`).  The `vmlinux` `stext` does not look for
appended DTBs.  If you need this feature you must use a compressed kernel.
====

.Complete ARM32 compressed kernel boot sequence — all phases

[cols="1,2,3,2", options="header", width="100%"]
|===
| Phase | Code Location | Action | Key Registers / Addresses

| 1. Bootloader
| U-Boot / EFI
| Load `zImage` to RAM, set `r0/r1/r2`, jump to entry
| `r0=0`, `r1=MachID`, `r2=DTB`, `pc=0x40010000`

| 2. NOP sled
| `head.S start:`
| 8 NOPs for legacy `a.out` skip; magic words for loader
| `pc=0x40010000`

| 3. Save ATAGS
| `head.S`
| `r1→r7` (MachID), `r2→r8` (DTB ptr)
| `r7`, `r8`

| 4. SVC mode
| `head.S safe_svcmode_maskall`
| Force SVC, mask IRQ/FIQ, save CPSR to SPSR
| `CPSR=0x1D3`

| 5. Find RAM base
| `head.S AUTO_ZRELADDR`
| `r0 = pc & 0xF8000000 = 0x40000000`
| `r0=0x40000000`

| 6. Compute ZRELADDR
| `head.S`
| `r4 = r0 + TEXT_OFFSET = 0x40208000`
| `r4=0x40208000`

| 7. Cache on
| `head.S cache_on`
| 1:1 page table at `r4−16K`; enable I+D cache
| `r3=page table base`

| 8. Stack + malloc
| `head.S restart:`
| `sp = 0x40A0ACC0`; `r10 = sp+64K = 0x40A1ACC0`
| `sp`, `r6`, `r10`

| 9. DTB check
| `head.S`
| Look for `0xD00DFEED` at `_edata`; not present here
| `r5=0` (no appended DTB)

| 10. Overwrite checks A+B
| `head.S`
| Both fail — kernel destination overlaps decompressor
| `r4=0x40208001`, `r10=0x40A1ECC0`

| 11. Self-relocate
| `head.S`
| Copy `restart…_edata` backwards to `0x41B7A600`
| `r5`, `r6`, `r9`, `r10`

| 12. GOT + BSS
| `head.S wont_overwrite:`
| Patch GOT entries with delta; zero `.bss`
| `r0=delta`, `r11`–`r12`

| 13. Decompress
| `misc.c decompress_kernel()`
| Inflate `piggydata` → `0x40208000` (~25.4 MiB)
| `r4=output`, `r1=malloc base`

| 14. Cache flush + off
| `head.S`
| Flush D-cache over kernel image; disable MMU/caches
| —

| 15. Enter kernel
| `head.S __enter_kernel`
| Restore `r0=0`, `r1=MachID`, `r2=DTB`; `mov pc, r4`
| `pc=0x40208000` (`stext`)

| 16. vmlinux startup
| `arch/arm/kernel/head.S stext`
| Enable MMU, set up page tables, → `start_kernel()`
| —
|===
